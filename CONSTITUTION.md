# SpecTorque Constitution

Version 1.0 · 2026-11-16

1. **Purpose.** Make requirements, assumptions and pending decisions visible before an agent implements them. Serve authors and reviewers across coding environments.
2. **Local by default.** Basic discovery, creation, analysis and review require no cloud account, model, GPU or telemetry. Network operations are explicit.
3. **Evidence before scores.** Every positive signal and finding must cite a document and line. Unknown, partial, missing and not applicable remain distinct. Non-applicability requires a reason and earns no points.
4. **Scientific honesty.** Attribute the EPIC source and state that automatic heuristics differ from human judgment. Correlation is not causation. No defect-reduction or model-quality claim without an appropriate controlled evaluation.
5. **One engine.** CLI, MCP, browser and host adapters consume versioned contracts and one rule implementation. An adapter may change presentation, never silently change scoring.
6. **Decisions belong to people.** Ask focused questions instead of inventing facts. Preserve identifiers, quantities, obligations, constraints and exclusions. Show differences and provenance before acceptance.
7. **Safe changes.** Proposals include a source hash. Reject concurrent changes and escaped paths. No automatic edits from imported documents or MCP tool calls. Explicit host/editor actions perform reviewed writes.
8. **Useful portability.** Deliver a common complete workbench and public-interface integrations for Claude Code, Codex, OpenCode and Pi. Publish exact versions and observed qualification separately.
9. **Bilingual quality.** English is canonical documentation; Spanish guides and EN/ES analysis are first-class. Neither language may silently receive weaker preservation controls.
10. **Accessible experience.** Support keyboard operation, readable evidence, responsive layouts and visible error recovery. A failed provider must leave source text intact.
11. **Fast, concrete delivery.** Reversible choices are made during implementation and briefly recorded in an issue or PR. No standing ADR approval process. GitHub Issues owns task state; the roadmap owns milestone scope.
12. **Open stewardship.** Apache-2.0 original work, preserved upstream licenses, reproducible examples and public contribution paths. Success means useful, repeatable workflows, not inflated scores or unsupported adoption claims.

The V1 excludes code/test implementation verification, model training and advanced enterprise features. Amendments must explain the user benefit, compatibility impact and evidence in the change request. Routine implementation choices need no constitutional amendment.
