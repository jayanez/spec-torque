# E1.2 clarification prototype

In the common workbench, select an E1.2 finding and read **Clarification question**, **No clarification question**, or **Review needed** under the existing evidence. The assistant offers one decision grounded in the selected requirement. The regular proposal editor remains the path for a human-reviewed change. The Spanish workbench presents equivalent guidance.

The prototype is local and deterministic. It recognizes bounded cases involving elapsed time, the start or end of a measurement, removal triggers, observable criteria for ease of removal, and observable adaptation behavior. Source revision, rule, evidence and scoring stay in the existing assessment. The question is generated on selection and leaves the assessment, source and proposal wording intact. It uses no provider, network requests or telemetry.

Fenced examples, blockquotes and HTML comments cannot supply clarification context. A plan or task line can contribute a concrete latency limit, measurement boundary, trigger, or decision-owner status when it starts with the unique requirement ID and the existing traceability graph resolves that reference within the feature. The resolver recognizes explicit labels such as `Latency limit: 300 ms`, `Measurement start: submit the search`, and `Evento disparador: confirmación`. It cites the original line. Current OpenSpec specifications and active change documents remain in their respective scopes. Conflicting values and unavailable owners lead to review. Outside the supported wording and links, the prototype can abstain.
