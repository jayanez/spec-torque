## Original layout regressions

`fixtures/formats/layouts.json` contains 14 original constructed cases: seven
layout-hint families in EN/ES, with 56 artifact records. These are deliberately
small examples of SpecTorque's documented hints, not files generated by the
named frameworks, conformance templates or independently labelled research data.
They require no external content, network access or model.

| Hint family | Constructed feature folder | Spec / plan / tasks basenames |
|---|---|---|
| Spec Kit | `specs/booking` | `spec.md` / `plan.md` / `tasks.md` |
| Spec Kitty | `.kittify/specs/booking` | `spec.md` / `plan.md` / `tasks.md` |
| OpenSpec | `openspec/changes/booking` | `specs/rooms/spec.md` / `design.md` / `tasks.md` |
| Kiro | `.kiro/specs/booking` | `requirements.md` / `design.md` / `tasks.md` |
| BMAD | `_bmad-output/planning-artifacts/booking` | `prd.md` / `architecture.md` / `tasks.md` |
| ZeeSpec | `.spec/booking` | `what.md` / `plan.md` / `tasks.md` |
| Generic | `product/booking` | `prd.md` / `plan.md` / `tasks.md` |

Each case is nested under its own application and includes an archived duplicate
ID with an opposite obligation. Archives must not contribute evidence or active
contradictions. Where there is no recognized feature marker, the current parent
folder defines the feature: archived BMAD/ZeeSpec/generic paths consequently have
a separate archive feature ID. That fallback is not proof of semantic ownership.
The same FR-001 is reused across all active features; plans/tasks must resolve it
only locally. Removing one definition must leave its two references unresolved
rather than resolving against another feature or archive.

`tests/formats.test.ts` exercises actual bounded filesystem discovery and direct
classification with POSIX and Windows separators, exact roles/feature/archive
labels, reference scoping, normative/measurement evidence and unknown states when
companion documents are absent. The baseline parser already handles these declared
paths; this increment adds coverage, not new classification or scoring behavior.

Run `node --import tsx --test tests/formats.test.ts` after locked dependency
installation. `npm run check` includes the corpus. These checks do not establish
precision/recall or framework-wide compatibility.

## Calibration sample

The [manifest](../fixtures/calibration/manifest.json) defines 28 original project
sets, one EN and one ES per family in each of the development and evaluation
partitions. Projects range from one Markdown artifact to a medium tree with
companion files. Original content uses Apache-2.0. Each case records its layout
reference, provenance, context, license and transformations. Each included file
records its path, language and SHA-256. Structural examples used to fix behavior
moved from the reserved partition to controls, with fresh reserved examples
for both affected families.

| Family | Added coverage |
| --- | --- |
| Spec Kit | Numbered feature folders, data model, acceptance criteria and a bare `specs/` attribution control. |
| Spec Kitty | `kitty-specs/<mission>/`, Markdown work packages under `tasks/`, and a YAML discovery negative. |
| OpenSpec | Proposal context, design, delta specs, current specs and dated archives. The external control is a published EN conventions spec at revision `e6539de023915e36848b351ea737ca8e192e8538`. Its [MIT license](../fixtures/calibration/external/openspec-conventions/LICENSE) accompanies the exact source bytes. |
| Kiro | Requirements, design, tasks and conditional requirement lines. |
| BMAD | PRD, architecture, epics and stories within documented output shapes. Cross-directory story ownership remains unverified. |
| ZeeSpec | `.spec/` question files and upstream/downstream context. `what.md` supplies the spec and `how.md` the plan for the sampled layout. |
| Generic PRD | Standalone PRD, companion files and mixed nested projects. |

The mixed workspace includes repeated basenames and IDs across projects,
root and project-local instructions, an in-feature duplicate, an unresolved
reference, and archived opposition. A selected feature inherits active
instructions from its ancestor directories. Archives remain outside active
analysis. The ZIP regression verifies both nested paths and bilingual bytes.

Open a workspace at the project root to retain layout context. Individual
Markdown files and flat uploads have only the path information supplied by
the caller. An ordinary `specs/` folder can produce a Spec Kit layout hint;
actual producer identity can remain unknown. ZIP is an export format.
YAML manifests, cross-project semantic references, inferred BMAD ownership,
arbitrary producer layouts, and semantic interpretation of quotations or
scenario prose are outside the evaluated behavior. Candidate paths and known
historical conventions are bounded by the existing discovery limits.

## Reproduce

With the locked project dependencies available and Node 22.20 or newer, run:

```sh
node --import tsx --test tests/formats.test.ts tests/normative.test.ts
npm run corpus:report -- --packet
npm run corpus:report -- --baseline 8c1ace3cf0e8b562af4f3bf99c4bc16220ac98b8 --labels fixtures/calibration/agent-reviews.json
```

The report uses Git and tar to read both engines from their committed
revisions in a temporary directory. Commit local engine edits before
comparing them. The report exercises filesystem discovery, the shared
classifier and the real analyzer over both engines. Each run prints its
output directory under `.spec-torque/corpus/`. The JSON includes the unit,
source line, prediction for both revisions and the reference state. The
Markdown table reports counts and rates by partition, rule, framework and
language, with denominators. The report records the commit, engine, rubric,
manifest and packet identities.

Use the [annotation guide](corpus-labeling.md) to collect independent
judgments, then rerun with `--labels <reviews.json>`. A reference may be
positive, negative, unknown, unsupported, pending or disputed. The report
keeps reference unknowns and engine abstentions visible. The precision,
false-positive and recall denominators cover decided cases and the coverage
denominator also includes abstentions on binary references. An incomplete
group withholds rates and a zero denominator is shown as `N/A`.

The same interpretation guide can be applied in a provisional agent review.
For that path, add `"kind": "agent"` and a `"model"` ID to each agent reviewer
and adjudicator in the review file. The report records that provenance.
Independent sessions hide other judgments and detector output, though
reviewers using the same model can still make correlated errors. Agent
metrics describe model judgments on this bounded sample. Human review is
a separate basis for claims about requirements quality.

## Observed agent comparison

[Agent annotations](../fixtures/calibration/agent-reviews.json) preserve both
blind sessions and the adjudication session. All three used OpenAI Luna Latest
(`gpt-6-luna`). The two independent sessions agreed on 689 of 716 propositions
(351/363 EN, 336/351 ES, 2/2 language-neutral). A third session adjudicated 27
disagreements. The final labels comprise 422 positive, 291 negative and
three `unknown` references. The latter concern possible permission versus
descriptive possibility and the ownership of a bare `specs/` hierarchy.

The following counts compare engine 0.1.1 at `8c1ace3` to engine 0.1.3 on the
reserved lexical sample. Each row reports the same propositions before and
after. The full report retains the per-framework breakdown and each error.

| Rule | Language | Units | TP | FP | TN | FN | Negative-reference abstentions |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| E1.2 | EN | 21 | 6 → 6 | 0 → 0 | 12 → 11 | 1 → 1 | 2 → 3 |
| E1.2 | ES | 21 | 3 → 6 | 0 → 0 | 7 → 7 | 4 → 1 | 7 → 7 |
| E1.4 | EN | 21 | 14 → 14 | 4 → 3 | 1 → 1 | 0 → 0 | 2 → 3 |
| E1.4 | ES | 21 | 14 → 14 | 0 → 0 | 0 → 0 | 0 → 0 | 7 → 7 |

These rows have zero positive-reference abstentions. EN date phrases can now
abstain when there is no other requirement signal, which lowers evaluated
coverage. Remaining errors include English uses of `May` as a name or noun
modifier, a written-out timing unit and a Spanish rate whose comparator comes
after the unit. The reserved lexical cases were held out of rule selection.
The documented OpenSpec proposal path was also a discovery regression in the
development sample. The broader comparison uses a directed corpus with small
denominators and potentially correlated model judgments.
